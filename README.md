# pmk61 — линия МК-61

Эмулятор программируемых калькуляторов **линии МК-61** и её расширения.

Проект отдельный от линии Б3-34 намеренно: 61-я машина — не «34-я с добавкой», у неё
своя косвенная адресация, 15 регистров и 105 шагов программы. Держать обе линии в одном
репозитории значит каждый раз проверять, что правка для одной не сломала другую.

## Где что лежит

| Проект | Линия | Профили | Статус |
|:---|:---|:---|:---|
| `mk-emulator` | Б3-34 | 34 | эталон, **не трогаем** |
| `pmk52` | Б3-34 → МК-54 → МК-52 | `b3-34`, `mk-54`, `mk-52`, `ext52` | развитие линии 34-го |
| **`pmk61`** | **МК-61** | **`mk-61`, `ext61`** | этот проект |

## Правила проекта

1. **Профиль исторической модели не расширяем.** `mk-61` — ровно 105 шагов, 15 регистров,
   только документированные команды. Никаких «а давайте добавим» внутри него.
2. **Всё придуманное — только в `ext61`**, и в интерфейсе он подписан как экспериментальный,
   а не как настоящий калькулятор. Импровизация не должна выглядеть историей.
3. **Неизвестный код не выполняется** и не угадывается: он помечается как неизвестный.
4. **Ядро меняется только при доказанном баге.** Различия моделей живут в `profiles.js`.

## Источник данных

Документация — руководство и разбор недокументированных возможностей из
[`greagre/pmk-android`](https://github.com/greagre/pmk-android/tree/main/instruction):

- `instruction/instruction.html` — руководство по эксплуатации (Б3-34, МК-52, МК-54, МК-61);
- `instruction/undocument_features.html` — недокументированные возможности + приложение «Все команды» (256 кодов).

Ни один код в таблице не берётся «по памяти»: только из этих двух документов.

## Что уже известно про МК-61 (зафиксировано)

- Код регистра — одна шестнадцатеричная цифра: `R0…R9` = `0…9`, `Ra` = «−», `Rb` = L,
  `Rc` = C, `Rd` = D, `Re` = E. `F` в командах с регистром — алиас `R0`, а `#F` — `R9`.
- `4r` — запись в регистр, `6r` — чтение; косвенные: `Lr` (запись), `Dr` (чтение),
  `8r` (БП), `7r` (`x≠0`), `9r` (`x≥0`), `Cr` (`x<0`), `Er` (`x=0`), `-r` (ПП).
- Модификация адреса при косвенной адресации: `R0–R3` → −1, `R4–R6` → +1, `R7–Re` → без изменений.
  Выполняется только когда адрес действительно вычисляется (у условного перехода — при невыполнении условия).
- Условный переход `57/59/5C/5E`: условие **выполнено** → адрес пропускается, идёт следующая
  команда; **не выполнено** → переход по адресу.
- Циклы: `58` = `F L2`, `5A` = `F L3`, `5B` = `F L1`, `5D` = `F L0`.
- `3E` — копирование Y в X (и X→X1), не влияет на X2; `3D` — дубль `2A`.
- `0C` — **ВП** (ввод порядка), а не `В↑`.
- Стек: X, Y, Z, T + X1. Возврат из подпрограмм — до 5 уровней, `В/О` берёт верхнюю +1.

## Порядок работ

1. Перенести `core.js` из `pmk52` (ядро одно, параметры моделей уже вынесены).
2. Написать `profiles.js` только для линии 61: `mk-61` и `ext61`.
3. Прогнать контрольные программы на `mk-61`.
4. Разобрать по документации, как МК-52 адресует 512 шагов, — пригодится для `ext61`.
5. Только после этого — интерфейс, декодер, импорт.
